# 校园失物招领信息管理系统
# 五人分阶段开发与多次合并分工方案

版本 2.0    2026年10月15日    组长 高鸣远

本方案供高鸣远、郭金滔、孙睿、袁运轩、杨程共同执行。我们采用四轮开发，每轮五人分别交付一个可验收的 PR，由高鸣远逐个合入 develop；全部模块联调完成后，再发起 develop 到 main 的发布 PR。建议共 20 个功能或集成 PR，加 1 个发布 PR。每个 PR 内可以多次提交，必要的修复可追加 PR，不为凑次数提交空改动。

## 一 项目目的与执行基线

项目题目为基于 SSM 的校园失物招领信息管理系统设计与实现。学生登记寻物或招领信息，审核人员审核和发布，学生申请认领，经核实及实际交接后结案。后台同时管理用户、角色权限、分类、内容和操作日志。

实验目的是掌握 SSM 手动整合、Controller 与 Service 与 Mapper 分层、参数校验、统一异常、声明式事务和 AOP 权限，并用真实业务验证分页、批量、逻辑删除、自动填充及并发控制。协作目标是让每个人都能说明自己的接口、页面、测试和 Git 提交。

**技术要求** 严格使用 Spring 加 Spring MVC 加 MyBatis，禁止 Spring Boot、Boot starter、Boot 自动配置和 Boot 打包插件。按学校要求保留 MyBatis-Plus 增强，采用手动接入；JDK 11、MySQL 8、Tomcat 9，交付 WAR。

**已有基础** 当前仓库已有可构建 SSM、公共响应和异常、分页及校验、十张业务和关联表、数据库安装升级脚本、系统健康接口。历史记录中 22 项基础测试通过是已有基线证据，各轮仍需重新运行并增加本模块业务验证。注册登录、分类、信息、审核认领和业务页面属于后续开发任务。

校园选题对应学校的 CMS 升级课程项目；实验二原题 EMP 员工管理 MIS 如需单独提交，按教师安排完成。本方案不将校园项目直接等同于已完成 EMP 实验。

仓库 https://github.com/andong163/campus-lost-found-ssm

开始前五人均从最新 develop 复现构建，记录本机环境。仓库曾调整提交身份；持有旧副本的成员先备份自己的开发内容，由高鸣远协助迁移到新基线，之后共同维护的历史不再随意重写。

### PR 编号的含义

计划编号采用 GMY R1、GJT R1、SR R1、YYX R1、YC R1，分别代表成员和轮次。下文的编号只是计划 ID，不是 GitHub 实际的 PR 号码；实际号码及合并提交在文末登记。

每个人每轮先完成可编译的小提交，例如数据访问、服务与校验、页面接入、异常测试和联调修复。每轮完成后发起一个 PR，避免一次提交整套系统。每合并一个 PR，下一位提交人同步最新 develop 并重新验证依赖，再由高鸣远继续合并。

## 四 高鸣远分阶段任务

高鸣远维护分支 feature/gaomingyuan-base，负责公共基础、接口协调和全部合并。基础工程已有的功能先复核复用，不重复记作新业务成果。

### GMY R1 固定基线和公共接口

核对 JDK 11、WAR、手动 SSM 配置、私密配置排除和现有测试。汇总五人的 DTO 字段、错误码、权限码、分类接口、状态命令及单条写操作的版本约定；确定公共页面和各模块目录。发布十表字段与接口归属清单，分配数据库迁移编号。

验收交付为可复现的构建记录、接口约定、目录样例和基础检查结果。通过实际 WAR 内容确认无 Boot、口令、测试类或本地工具，不将本地 Tomcat 辅助工具改成发布运行时。

### GMY R2 公共页面与统一请求组件

提供站点公共布局、导航、分页组件和同源 fetch 封装，与郭金滔对接登录状态和 CSRF。统一处理 400、401、403、409、503 的安全提示。各业务页面放独立文件，成员只接入公共组件。

验收时用真实 API 检查登录状态切换、退出、分页和错误提示，页面不显示 SQL 或堆栈。其他成员能接入自己的页面，不需要同时改公共首页。

### GMY R3 集成用例与实际部署验证

建立跨模块 HTTP 用例、测试账号准备与清理方式，复验前两轮注册、建分类、草稿和审核。核对 SQL 迁移、主接口文档和测试环境配置，在外部 Tomcat 9 部署实际 WAR。

验收要求用专用测试库复现流程，测试数据可清理，真实业务库不被测试覆盖；记录环境、请求结果和实际错误。各成员提供本模块接口片段，高鸣远汇总主接口文件。

### GMY R4 全组验收与交付材料

其他四人的第四轮 PR 合入后，运行全量回归，复现空库安装、旧库升级和外部部署。整理架构图、E R 图、业务流程图、运行说明、测试汇总和源码包，逐项核对学校评分点。

验收要求完整演示发布、认领、核实、交接结案及寻物找回；正常与异常用例都有证据。修复应由责任人提交，高鸣远完成协调和合并，不以本人身份代替组员贡献。

## 五 郭金滔分阶段任务

郭金滔维护分支 feature/guojintao-auth，负责 auth 包及用户、角色、权限相关表。为所有模块提供同一套 CurrentUser、权限注解、Session 和 CSRF 入口。

### GJT R1 注册登录与真实身份基础

完成注册、登录、退出、当前用户查询、登录拦截、权限注解及 Spring AOP。密码采用带盐哈希，注册只分配 EDITOR 学生角色。提供本机一次性管理员初始化方式，从本地输入或环境读取口令，不把明文密码写入仓库。

验收注册伪造角色无效、重复用户名拒绝、未登录 401、无权限 403、退出后原会话失效；受保护的直接 API 调用也必须拒绝。提供给孙、袁、杨的是真实用户和权限结果。

### GJT R2 用户与角色权限管理

完成用户分页、启停、角色分配、权限维护与种子清单。使账号停用或角色调整对既有会话及时生效。保护必要的管理员可管理性，具体规则在公共约定中确认。

验收学生不能修改本人角色或替他人分配权限，停用账号不能继续使用旧会话；撤销权限后对应 API 立即拒绝。接口响应不含密码或哈希。

### GJT R3 身份模块页面与公共布局接入

完成登录注册页、用户列表、角色权限管理页，接入高鸣远公共布局、菜单和请求组件。实现表单反馈、登录状态显示、退出和跳转；与各人联调权限码及写操作的 CSRF。

验收不同角色显示的入口与实际 API 权限一致，手工构造请求不能绕过校验；缺失或错误的 CSRF 被拒绝。页面交互与服务端验证同时保留。

### GJT R4 权限矩阵回归与身份材料

逐个核对公开、学生、审核员、只读和管理员的接口权限及资源所有权；修复会话、启停和角色边界。提交身份模块操作说明、ApiFox 用例、测试记录和真实问题修复过程。

验收至少覆盖合法访问、未登录、无权限、越权、停用和撤权。与其他模块一起检查本人规则及审核回避，不能只验证登录成功。

## 六 孙睿分阶段任务

孙睿维护分支 feature/sunrui-category，负责 category 包、分类表、分类树及查询组件。袁运轩和杨程通过孙睿提供的统一规则判断分类可用性。

### SR R1 分类基础与可绑定接口

完成分类 Entity、Mapper、新增管理接口、树查询及祖先有效性判断。提供可绑定分类校验和公开有效分类查询，拒绝不存在、已删除或任一祖先已停用的分类，并校验同级有效重名。

验收多层新增和树结构正确，公开树不出现停用子树。用真实权限组件保护写接口，并用测试演示分类对内容绑定的约束。

### SR R2 完整分类管理与页面

完成修改、移动、排序、启停、逻辑删除及分类管理页。防止移到自己或后代；有子分类或内容关联时拒绝删除。与高鸣远、袁运轩确认分类绑定和启停删除使用的事务与锁顺序。

验收循环、同级重名、非法父级、有引用删除和并发绑定等边界。父类停用须影响整个子树，页面错误提示与接口响应一致。

### SR R3 分类组件与查询次数优化

完成分类选择器、公开分类树、按子树筛选的共享能力。与袁运轩一起统一公开列表和公开详情的祖先有效性规则，避免逐条内容查询祖先造成 N 加 1。

验收子树筛选和停用隐藏正确，保留固定数据规模下的 SQL 次数、查询日志及优化前后结果。不得只写已经优化而不给出可复现实测。

### SR R4 并发边界与性能证据

复验分类停用、删除和内容绑定的并发边界，核对关联查询索引与 EXPLAIN，补全页面反馈、接口说明、测试及问题记录。

验收父类停用后公开列表与详情同时隐藏内容；原有认领仍按规则继续核实，但不能新建认领。记录优化前后 SQL 和条件，说明分类接口对内容与认领的影响。

## 七 袁运轩分阶段任务

袁运轩维护分支 feature/yuanyunxuan-article，负责 article 包、内容 Entity 与 Mapper、DTO、检索和相关页面。状态变更调用杨程统一工作流，不另写一套发布和审核状态规则。

### YYX R1 物品数据访问与本人草稿

完成 LOST 和 FOUND 共用 Entity、Mapper、公开与私有投影，提供本人草稿新增及草稿详情。固定杨程需要的锁定查询和条件更新契约；作者从真实 Session 获取，创建状态由服务端设置为 DRAFT。

验收不能伪造 authorId、发布状态或客户端版本；他人不能查看私有草稿。公开投影不含联系方式和认领证据，JSR303 基础字段校验有效。

### YYX R2 信息编辑与审核接入

在 YC R2 合并后，完成我的信息分页筛选、草稿编辑、详情和编辑页，接入提审、撤回、改为草稿及重新提审。字段保存和状态变更在同一事务中完成。

验收学生只维护本人内容；待审先撤回才能编辑，已发布先下架再改稿重审；过期版本或非法状态返回 409。页码、页大小、排序和输入校验符合公共约定。

### YYX R3 公开检索与批量管理

完成公开列表详情、多条件模糊查询、日期和类别子树筛选及页面；接入单条发布下架和批量发布下架删除，后台管理列表复用统一工作流。

验收公开内容必须已发布、未删除且分类全部祖先有效。批量限制 1 到 100 个不重复正整数；任何记录越权、缺失、状态或版本冲突都整批回滚，排序稳定且排序字段使用白名单。

### YYX R4 联系方式与信息端回归

完成单条联系方式读取接口、认领入口链接、已结案历史展示和信息端性能隐私回归。FOUND 的可读性调用杨程认领规则，不由前端或 ArticleService 自行判断。

验收公开列表详情无私密信息；LOST 联系方式只通过登录后的单条入口读取并审计；FOUND 只向核实通过者、作者及有需要权限的审核人员开放。页面安全转义，结案历史禁止新认领。

## 八 杨程分阶段任务

杨程维护分支 feature/yangcheng-review-claim，负责 review、claim、audit 包。旧方案曾使用 review 结尾；本方案统一为 review-claim。已有旧名分支先由高鸣远确认映射，不重复建立两个业务实现。

### YC R1 审计基础与状态契约

完成结构化审计写入、授权日志分页查询、审核记录 Mapper，以及后续工作流所需的认领查询与关闭操作契约。与袁运轩冻结 ItemWorkflowService 的状态命令和单向依赖，先交付可运行的审计能力。

验收日志关联 requestId，仅记操作者、目标、动作、结果及必要摘要，不记密码、正文、联系方式或证据。日志异常不能引导前端重复执行已成功业务；审核记录仍必须随业务事务保存。

### YC R2 内容状态与审核工作台

依赖 YYX R1 的稳定 Mapper，实现提审、撤回、批准驳回、转草稿、发布下架和删除前状态校验；提供审核待办、历史及页面。状态、审核记录和有关联申请的处理保持同一事务。

验收不能审核本人内容，非法转换或过期版本返回 409；已批准认领阻止编辑下架删除，下架关闭待核实申请。注入失败后记录与状态都回滚，不留下半完成数据。

### YC R3 认领申请与核实

完成申请、本人的申请列表、物品申请列表、核实批准驳回、撤销及页面，提供 FOUND 联系方式的读取策略。请求先锁定物品，再处理申请，沿用数据库的两类唯一约束。

验收仅能申请他人已公开且 OPEN 的 FOUND；同人同物最多一个有效申请，同物最多一个 APPROVED；审核回避本人申请及利益相关内容。并发批准最多成功一个，批准不等于归还或结案。

### YC R4 实际交接与业务审计闭环

完成 FOUND 发布者确认真实交接，以及 LOST 作者确认找回；完善日志查询页和审核认领的异常矩阵。FOUND 交接使申请 COMPLETED、物品 RESOLVED、resolved_at 写入，并关闭其他待核实申请。

验收上述交接操作同事务成功或回滚；重复交接、非本人结案和已结案后新认领均拒绝。分类停用后旧申请可继续核实，新增申请不能绕过分类可用性判断。

## 九 跨模块接口与共同规则

下列接口名称是开发约定，实际签名在第一轮由维护人和高鸣远共同确认，不表示当前仓库已经实现这些接口。

| 接口或数据 | 唯一维护人 | 使用关系与验收重点 |
| --- | --- | --- |
| CurrentUser 与权限组件 | 郭金滔 | 全组取得真实身份、权限和 CSRF，业务不能相信请求传入的操作者 ID |
| CategoryAccessService | 孙睿 | 内容绑定、公开检索、发布及认领统一检查分类和祖先有效性 |
| Article Entity 与 Mapper | 袁运轩 | 杨程通过 Mapper 或领域查询访问内容，锁定查询和条件更新签名保持稳定 |
| ItemWorkflowService | 杨程 | 袁调用提审、撤回、编辑转换、发布下架、删除校验和结案，集中维护状态 |
| ClaimReadPolicy 与审计服务 | 杨程 | 袁用认领策略判断 FOUND 联系方式；全组提交安全的结构化审计字段 |
| 公共配置与 SQL 主稿 | 高鸣远 | 汇总迁移、接口和公共布局变更，各模块不分别修改整套基础配置 |

依赖方向为 ArticleService 调用 ItemWorkflowService，工作流再访问 ArticleMapper。工作流不能反过来依赖 ArticleService，避免循环注入和两套状态逻辑。通过公开 Service 代理进入事务，内容字段与状态更改在同一事务完成。

内容状态为 DRAFT、PENDING_REVIEW、APPROVED、PUBLISHED、REJECTED、OFFLINE；物品处理状态为 OPEN 或 RESOLVED；认领状态为 PENDING、APPROVED、REJECTED、CANCELLED、COMPLETED。审核批准、公开发布、认领核实和实际交接是不同动作。

学生仅维护本人信息和申请；普通注册不能指定管理角色；审核人员执行回避规则。分类失效时公开列表和详情采用一致过滤。批量操作先检查全部权限与条件，再按一致锁顺序处理，任何一项失败整批回滚。

## 十 每轮联调场景与停合条件

### 第一轮验证基础依赖

按高、郭、孙、袁、杨顺序合并。先用真实账号注册登录，再由管理员建可用分类，学生创建本人草稿，最后授权查询审计。验证其他账号不能读取草稿，未登录和无权限分别返回 401 和 403。

如果下游必须硬编码用户、绕过分类规则或注入空工作流才能启动，停止合并，先修复缺失契约。第一轮允许通过 ApiFox 验证，不声称完整网站页面已经交付。

### 第二轮验证内容审核

按高、郭、孙、杨、袁顺序合并。学生修改草稿、提审，审核员驳回，学生修改重提，再由审核员批准；另测撤回、非法直接编辑和自审。杨程基于第一轮 Mapper 实现工作流，袁运轩随后接入真实服务。

发现状态先改而正文后失败、审核记录与内容不同步或事务自调用失效时，停止合并并补回滚测试。临时返回成功不属于验收成果。

### 第三轮验证公开与认领

按高、郭、孙、杨、袁顺序合并。授权人员发布 FOUND，游客检索，其他学生提出认领，审核员核实；同时检查公开 DTO、分类子树、多条件检索和批量整批回滚。

并发批准出现两个成功、本人或私有物品可申请、列表泄露联系方式等问题，修复后再合并。核实通过仍显示待交接，不直接标成物品归还。

### 第四轮验证交接与发布质量

按郭、孙、杨、袁、高顺序合并。由发布者确认交接后，检查认领完成、物品结案、时间写入和其他待申请关闭；再测 LOST 本人找回。覆盖分类停用、重复交接、撤权及联系方式审计。

高鸣远最后在专用测试库和外部 Tomcat 复验完整流程。缺少可复现安装步骤、存在 Boot 依赖、私密文件入包或业务异常仍造成部分成功时，不进入发布 PR。

## 十一 组员首次下载与配置

先登录本人 GitHub 账号，在浏览器接受私有仓库邀请。邀请页面只用于浏览器；Git 使用以 .git 结尾的仓库地址。在准备存放项目的目录执行下列命令。

```bash
git clone -b develop https://github.com/andong163/campus-lost-found-ssm.git
cd campus-lost-found-ssm
git config user.name "本人GitHub用户名"
git config user.email "本人GitHub已验证的邮箱"
```

每人填写自己的身份，不能五个人都配置成 andong163。高鸣远的账号为 andong163；其余成员使用各自的实际账号。邮箱应加入对应 GitHub 账号并验证，以便关联提交。

### 创建自己的分支

从刚下载的 develop 创建。以下为郭金滔的例子，其他成员替换分支名；已有分支改用 git switch 切换，不重复执行创建命令。

```bash
git switch -c feature/guojintao-auth
```

个人分支为高鸣远 feature/gaomingyuan-base、郭金滔 feature/guojintao-auth、孙睿 feature/sunrui-category、袁运轩 feature/yuanyunxuan-article、杨程 feature/yangcheng-review-claim。本方案复用个人分支完成四轮 PR，保留到全部验收结束，每轮先同步 develop。

### 本地环境和口令

准备 JDK 11、Maven、MySQL 8，并按照 README 选择空库初始化或旧库升级。首次将 config/jdbc-local.properties.example 复制为 src/main/resources/jdbc-local.properties，在本机填写账号密码。各人的数据库口令和本地路径不互相复制进代码。

Windows PowerShell 中执行 ./scripts/build.ps1 验证构建；./scripts/run-dev.ps1 用于本地开发。正式交付为 target/cms.war 加外部 Tomcat 9，不使用 Boot 启动命令。

## 十二 多次提交与下一轮同步

以郭金滔第一轮为例，先分步完成数据访问、身份服务和权限，再补测试和实际修复。提交说明用中文，描述本次已经完成的内容，不把下一轮未验收的大功能塞进当前 PR。

```bash

```

其他新增的 Mapper XML、页面、测试和文档也按实际路径暂存。每次先看暂存内容；以上路径仅为本模块示例，不能只提交 Java 而漏掉实际必需的资源文件。

本轮功能和自测完成后，先保持工作区干净，再把最新 develop 合入自己的分支；有冲突则与文件维护人确认内容，解决后重新构建。

```bash
git fetch origin
git merge origin/develop
```

构建通过后上传。第一次加 -u 建立跟踪关系，后续可直接 git push。


## 十三 高鸣远审核与合并操作
