# 本地数据库安装与升级

## 选择命令

- 全新数据库：`./scripts/bootstrap-db.ps1`；已有任何表即拒绝初始化。
- 旧 CMS 九表：停止本项目服务，运行 `./scripts/upgrade-db.ps1`；已升级时可再次执行验证。

工具使用外置私密文件或环境变量，尊重 jdbc.url 中的本机端口，只接受 localhost／127.0.0.1／IPv6回环和 cms_content。远程或其他数据库被拒绝；口令不作为命令参数、不写日志。

## 升级步骤

1. 获取 MySQL 命名锁，避免两个升级工具同时运行；原项目内容表必须存在。
2. 查询六个新字段。六个全部存在则跳过 ALTER；若只存在部分，停止并要求核对结构。
3. 老表尚无新字段时，要求 cms_article 为空。存在旧文章则停止，不自动编造信息类型、时间、地点或联系方式。
4. 执行 001-campus-item-columns.sql，新增招领字段、处理状态约束和组合索引。
5. 执行 002-claim-request.sql，补充认领表和唯一索引；已有表不会被覆盖，验证会检查所需字段与索引。
6. 仅将旧的默认角色名称“编辑人员／普通用户”改为“学生／只读用户”，保留角色代码与自定义名称。
7. 验证四角色和新结构，用临时用户、分类、招领、申请验证重复申请和互斥通过，再回滚探针数据。

MySQL DDL 在阶段之间提交，整个升级不能声明为一笔可回滚事务。两个结构阶段可在中断后检查并重跑；部分未知结构应人工修复。命名锁仅约束升级工具，执行前需停止会写入本库的项目进程。

## 结构说明

新增 item_type、event_time、location、contact_info、resolution_status、resolved_at。数据库要求 OPEN 的 resolved_at 为 NULL，RESOLVED 有结案时间。内容发布与结案分别管理。

认领表有两个存储生成列和唯一索引：同一物品同申请人仅一条 PENDING/APPROVED 记录；每物品仅一条 APPROVED 记录。取消、驳回、完成的旧申请保留。服务仍需权限、状态、行锁和同事务结案规则，不能把数据库约束当作完整业务实现。

初始化脚本和增量脚本不含真实账号口令、DROP或TRUNCATE。实际验证情况见 test-record.md。本机已将原空内容库升级，业务账号和演示内容仍未创建。
