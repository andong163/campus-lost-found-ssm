# 需求分析初稿

## 目的与范围

基于实验二的 SSM 能力开发企业资讯与知识 CMS，管理新闻、公告及知识文章。系统核心是内容创建、审核、发布、检索和下架；采用单体分层工程，五人按业务模块协作。首阶段交付基础框架，后续业务按分工完成。

## 角色与业务场景

| 角色 | 主要任务 | 约束 |
|---|---|---|
| 管理员 | 管理用户、角色、分类，查看日志及全量内容 | 关键管理接口也需要权限 |
| 编辑 | 创建和维护本人文章，提交审核 | 不能修改他人文章或自行绕过审核 |
| 审核员 | 查看待审核内容，批准或驳回并填写意见 | 只有待审核状态可处理 |
| 普通用户或访客 | 检索并阅读公开内容 | 仅已发布、未删除、分类可用的内容 |

具体权限编码由郭金滔与各模块确认；角色只是默认组合，接口仍需细粒度权限。注册默认低权限，管理员身份不能通过客户端传参获得。

## 必做需求

1. 用户注册、登录、退出、角色分配，登录拦截及 Spring AOP 权限校验。
2. 多级分类新增、编辑、排序、删除、启停，分类循环与文章关联校验。
3. 文章新增、编辑、逻辑删除、批量发布/下架、分页与多条件检索。
4. 审核流程、意见与记录，同一状态入口及并发修改约束。
5. 参数校验、统一错误结果、事务与操作日志；请求日志不得记录密码。

## 工程与数据要求

Controller/Service/Mapper 分层，数据库六类核心数据加关联及审核记录共九表。主键、外键、唯一约束、字段长度和索引规范。批量第一版整批成功或回滚，排序字段白名单，单页最多100条；公开查询和管理查询必须分开权限与状态过滤。

进阶验证 MP 分页、逻辑删除、自动填充及乐观锁；文章作者/分类列表避免逐行关联查询。索引效果通过 SQL 次数、EXPLAIN 和耗时实际验证，不把建索引等同于已优化。

## 分阶段验收

基础工程：可构建 WAR，Web链路、数据库、校验和事务测试通过。

模块开发：各成员提交接口、页面、数据库变化与正常/异常测试。

整体验收：管理员建分类和配置角色，编辑创建并提交文章，审核员处理，授权人员发布，普通用户检索，内容下架，管理员查询日志。验证未登录、越权、非法状态、非法参数及事务回滚。

最终提交源码历史、SQL、接口文档、测试证据、需求与设计图、报告及 AI 人工修改记录。当前基础工程仅实现 system 健康/就绪接口，不能按上述最终验收流程演示全部 CMS。
