# 校园失物招领需求基线

对应配套需求规格说明书和五人分工方案，日期 2026年10月12日。本文件给源码使用者提供开发入口，以下业务均为目标需求，当前实现范围以 README 和验证记录为准。

## 项目目的

基于 SSM 管理校园寻物和招领内容，形成登记、审核、发布、检索、认领核实、线下交接与结案流程。后台管理用户、角色权限、物品分类、内容与日志，覆盖学校 CMS 升级评分要求。

## 技术约束

严格采用 Spring + Spring MVC + MyBatis 的传统 SSM 架构，禁止 Spring Boot 及其 starter、自动配置、启动入口与打包插件。通过配置类显式整合 IoC、AOP、事务、DispatcherServlet、数据源和 Mapper，交付 WAR 并部署到外部 Tomcat 9。MyBatis-Plus 按学校评分要求作为 MyBatis 增强组件保留，采用非 Boot 的手动配置方式。

## 用户与权限

游客只浏览公开信息。EDITOR 在界面显示为学生，默认维护本人信息、提审、单条下架本人信息、申请认领和确认交接；注册不能传入角色。REVIEWER 负责审核、认领核实及授权发布，不能审核本人内容或本人申请。ADMIN 管理用户、角色、分类、内容和日志，也遵守业务状态约束。VIEWER 为只读账号。

登录采用同源 Session，退出销毁会话，停用与角色修改即时生效。Spring AOP 校验权限，业务服务校验所有权和状态。密码带盐哈希；本地凭据排除 Git 与 WAR；写操作需 CSRF 或等效同源防护。

## 必做业务

1. 用户注册登录退出、角色权限、启停用户、登录拦截与 AOP 权限。
2. 多级物品分类 CRUD、排序和启停，拒绝循环及同级有效重名，有子分类或内容不能删除。父级停用影响全部子树。
3. 寻物 LOST／招领 FOUND 信息 CRUD、分页、多条件模糊筛选、稳定排序及批量发布下架删除。
4. 内容审核、驳回意见与记录；统一状态入口，非法状态与过期版本返回 409。
5. 招领认领申请、核实、撤销与交接结案；寻物由作者确认找回。
6. 操作日志与联系方式读取审计、校验、异常、事务、逻辑删除与时间填充。

## 状态与私有数据

ArticleStatus 保留 DRAFT、PENDING_REVIEW、APPROVED、PUBLISHED、REJECTED、OFFLINE。ResolutionStatus 独立使用 OPEN、RESOLVED，审核批准不表示物品已经归还。ClaimStatus 使用 PENDING、APPROVED、REJECTED、CANCELLED、COMPLETED。

公开接口仅返回未删除、PUBLISHED、有效分类子树中的内容；已结案可展示历史，禁止新认领。公开 DTO 不包含联系方式和认领证据。登录学生可通过单条“联系失主”入口读取公开且 OPEN 的 LOST 联系方式并记日志；FOUND 仅向核实通过的认领人开放联系信息，作者与所需审核人员按权限读取。

## 认领约束

仅对他人公开且 OPEN 的 FOUND 申请。同用户同物品最多一个有效待核实或已批准申请，物品最多一个有效批准申请。核实通过后，发布者确认实际交接才完成认领并结案；同事务关闭其他 PENDING 申请。存在 APPROVED 申请时不能编辑、下架或删除；PENDING 情况下下架须同时关闭申请。类别停用后原申请可继续核实，不接受新申请。

数据库唯一索引作为重复及互斥保护，不替代权限、状态与事务。服务先锁定物品行，再处理申请；生成列不得由客户端或 Entity 任意写入。

## 验收与范围

五人分别完成接口、页面、自测和过程记录。统一验证正常流程、未登录与越权、非法状态、分类停用、批量回滚、版本冲突和认领互斥。进阶验证 MP、高级筛选、N+1 SQL 次数与 EXPLAIN，保留实测证据。
